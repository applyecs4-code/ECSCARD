# Apply ECS – Netlify + Supabase admin panel

The old PHP admin panel, rebuilt for Netlify.

| Before (PHP) | Now (Netlify) |
|---|---|
| SQLite file | Supabase Postgres (`supabase/schema.sql`) |
| `storage/files` (ID / photo) | Supabase Storage, **private** bucket `documents` |
| PHP sessions | Signed HttpOnly cookie (12 hours) |
| `mail()` | SMTP (nodemailer) |
| `receive.php`, `enquiry.php` | Netlify Functions `/admin-api/receive`, `/admin-api/enquiry` (old URLs still work via redirects, so forms need no changes) |
| Hiding pages via `.htaccess` | Edge Function `hide-pages.mjs` (returns 404) |
| Writing a `site-custom.css` file | `/site-custom.css` is now generated by a Function |

## What is in this zip
`site/` contains your **whole website** (198 pages, CSS, JS, images, sitemap, robots), already merged. Only this changed:
- `book.html`, `ecscardbooking.html` -> the form now posts to the admin panel backend (in `ecscardbooking` files upload straight to Supabase Storage).
- `contact.html`, `index.html`, `index1.html` -> `formsubmit.co` removed; forms post to the admin panel (Enquiries).
- Removed (not useful on Netlify / no longer needed): `.htaccess`, `*.php`, `vercel.json`, old `netlify/functions/send*.js` (Resend), `api/*.js` (Vercel style).
- **Stripe pages** (`cart.html`, `e-learning-checkout*.html`) use `/api/checkout` and `/api/create-checkout-session`. These Vercel-style files did not work on Netlify before either, so they were left untouched. The admin API prefix is `/admin-api/` so it does not clash with them.

## Folders
```
site/            <- your whole website (html, css, img ...)
admin-ui/        <- admin panel frontend (becomes /admin/ on deploy)
netlify/functions/api.mjs        <- the whole backend
netlify/edge-functions/hide-pages.mjs
netlify/lib/     <- shared code
scripts/build.mjs <- on deploy: copies the site, adds the design hook, builds the page list
supabase/schema.sql
```

## Setup (one time)
1. **Supabase**: create a new project at supabase.com -> *SQL Editor* -> paste all of `supabase/schema.sql` -> Run.
   Copy the `Project URL` and the `service_role` key from *Project Settings -> API*.
2. **Site files**: already done (the whole site is in `site/`).
3. **Push to GitHub**, then in Netlify use *Add new site -> Import from Git*. (Drag-and-drop deploy will **not** work because Functions and a build step are needed. With the CLI: `npx netlify deploy --build --prod`.)
4. For email via Resend: `SMTP_HOST=smtp.resend.com`, `SMTP_PORT=465`, `SMTP_USER=resend`, `SMTP_PASS=<your Resend API key>`, and `MAIL_FROM` with an address on your verified domain.
5. **Netlify -> Site configuration -> Environment variables**: add every value from `.env.example`:
   `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `SESSION_SECRET` (a long random string), `SMTP_HOST/PORT/USER/PASS`, `MAIL_FROM`. Then redeploy.
6. Open `https://your-site/admin/`. The **old login** (email + password) still works. Change it on the Account page.
7. Use *Settings -> Save + send test email* to check that email works.

## Pages & Design
- **Pages -> Hide**: the page returns 404 and its menu links are hidden (live within about 20–60 seconds).
- **Pages -> Delete**: a file in a live Netlify deploy cannot be deleted at runtime, so Delete = "hide + move to Trash"; **Restore** brings it back. To remove the file for real, delete it from `site/` and push.
- `sitemap.xml` is no longer updated automatically (the PHP panel used to edit it). Remove hidden pages from the sitemap manually.
- **Design**: changes appear on the site about 1 minute after saving (60 second CDN cache). The build script adds `<link href="/site-custom.css">` to every root `.html` file on each deploy.
- **New pages** cannot be created in the admin. Add the file to `site/` and push; it appears in the list automatically.

## Documents (ID / photo)
`ecscardbooking.html` uploads files straight to Supabase Storage (Netlify's request limit is about 6 MB, so a 15 MB file sent as base64 would fail). In the admin, a document link is a 60-second signed URL, never a public link.
Uploads abandoned before submit can remain in the `incoming/` folder; clear them from Supabase -> Storage now and then.

## URL note
The old `.htaccess` redirected `/page.html` to `/page` (301). On Netlify, turn on Site configuration -> Build & deploy -> Post processing -> **Pretty URLs** to get that. Both URLs will keep working.

## Tests (local, offline)

## Notifications (booking@applyecscard.co.uk + Admin)
Everything is saved in the Admin panel **and** emailed to `booking@applyecscard.co.uk` (more addresses can be added in Admin > Settings; booking@ always stays):
- Test booking / card application form (full data + uploaded ID/photo attachments) -> Admin > Bookings
- Contact / enquiry form -> Admin > Enquiries
- Someone adds a course to the cart, or enters name/email/phone at checkout and clicks Pay -> Admin > **Cart** (`site/track.js`)

The SMTP variables are required for email (`.env.example`). For the Cart tab, run `supabase/cart_events.sql` once in the Supabase SQL Editor.

## Admin features
Home (dashboard) · Upcoming tests (calendar) · Header (hide/show menu items and words) · Cart · WhatsApp / Call / Email quick buttons · CSV export (enquiries, cart) + full JSON backup · Customer auto-reply (Settings, default OFF).

## Live tracking + checkout leads
Admin > **Live** shows who is on the site now, which page, for how long, what is in their cart and, if they entered name/email/phone at checkout, those too (updates every 5 seconds). Run `supabase/live_visitors.sql` once.
Name/email/phone typed into the checkout drawer appear in Live straight away; clicking Pay creates a "Checkout started" entry in Admin > Cart plus an email (which course/test, which user).

## Update v2

### "Method Not Allowed" fix
Forms now post to the Function's real paths: `/admin-api/enquiry` (contact + home form) and `/admin-api/receive` (test booking + card form). The old `/admin/enquiry.php` and `/admin/receive.php` URLs still work via redirects, and opening them in a browser (GET) now opens the contact page instead of an error.
Enquiries now appear in Admin > **Enquiries** (and by email). If both saving and email fail, the customer sees a proper error instead of "Thank you".

### Important: run `supabase/upgrade_v2.sql` once in Supabase
(SQL Editor > paste > Run.) It lets the Live tab show what each visitor is doing and which test they are choosing. Everything works without it; that extra information just will not show.

### New admin features
1. **Customers** – which user booked which test / card, at which centre, for which date. Bookings + enquiries + checkouts are linked by email/mobile. CSV export. The Enquiries tab also shows whether that person has already booked.
2. **Live (upgrade)** – who is online, what they are doing now (filling the booking form / checkout / browsing), which test + centre they are choosing, cart, name/email/phone, their existing test if they are a customer, WhatsApp/Call buttons, "Block IP" button.
3. **Leads** – people who gave details at checkout / enquiry / live but did not book. Follow up, then mark "Done".
4. **Reports** – by test / centre / status for a date range (who booked which test), CSV export.
5. **Global search** (box at the top) – bookings + enquiries + cart together, by name / email / mobile.
6. **Alerts** – sound + browser popup + tab title on a new booking / enquiry / checkout (Bell button at the top).
7. **Blocked IPs (spam shield)** – block an IP from Settings or Live; it can no longer submit forms or be tracked.

### Header hide / show
Admin > Header: a switch next to every menu item. **OFF = hidden from the site, ON = shown.** Every click saves automatically and goes live in 10–20 seconds. Switching off a group (dropdown) also hides every link inside it; if all links are off, the empty dropdown hides itself. Any **word** (e.g. SAVE) can be hidden with a chip; remove the chip to show it again. Footer items are included.

## Update v3 – Contact form + Add to cart data in both email and admin

**Important: run `supabase/upgrade_v3.sql` once in Supabase** (SQL Editor > paste > Run). Without it enquiries are still saved, but the cart part will not show in the admin.

What changed:
- When the contact / home enquiry form is submitted, `track.js` sends the visitor id + cart items with the form. The enquiry email gets a "Cart" section and Admin > Enquiries shows a "cart" tag + the items.
- If a visitor fills the contact form first and adds to cart later (or the other way round), the two are linked: the cart email / Admin > Cart shows name, email and phone.
- Cart rate limit raised from 60 to 300 per IP per hour (so shared college / office IPs are not blocked).
- If an email fails, Admin > **Log** gets a `mail_failed` entry (with the reason). Data is saved in the admin first, so a failed email never loses a lead.

For email to work, `SMTP_HOST / SMTP_PORT / SMTP_USER / SMTP_PASS / MAIL_FROM` must be set in the Netlify environment. They are commented out in the zip's `.env`; that local file is not uploaded to Netlify, so add them in Netlify > Environment variables.

## Update v4 – Blogs (Admin > Blogs)

**Important: run `supabase/blogs.sql` once in Supabase** (SQL Editor > paste > Run). Then open Admin > **Blogs**: 10 starter blogs (courses / cards / tests) appear automatically as **Draft**.

- **Draft / Hidden = not visible on the site at all** (not in the list, direct link gives 404, not in the sitemap). Only a logged-in admin can use "Preview".
- **Make live** -> live at `/blog` and `/blog/<slug>`. **Hide** -> switched off again immediately (no cache). **Delete** = permanent.
- **+ New blog**: a new blog is always created as Draft. "Save & make live" publishes it straight away.
- Every blog ends with a **Related course** button (pick a course from the dropdown and the name + page fill in automatically).
- Format: `## Heading`, `- bullet`, blank line = paragraph, `**bold**`, `[text](link)`; or paste full HTML.
- A "Blog" link is added to the footer. To hide it, use Admin > Header. `/blog-sitemap.xml` lists live blogs only (you can add it in Google Search Console).
- Starter blogs are about 220–270 words; replace them with your own, longer content in Edit.

Test: `npm run test:flow` (no npm install needed, uses a fake Supabase) checks blogs live/hide, contact form + cart link and mail failure.

**Shortcut:** `supabase/run_all.sql` runs Cart, Live, enquiry-cart link and Blogs in one go. If you see the error "Could not find the table 'public.cart_events' in the schema cache", run this file in the Supabase SQL Editor.
